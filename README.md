# Frontend Test Runner Service

Executes BDD-generated Playwright test packages against live sites and harvests one recorded video clip per scenario for the `demo_video` pipeline. Port 6316.

## What Frontend Test Runner Service Does

When the orchestrator's `demo_video_record` stage needs footage, it submits a job to this service with either a `bdd_job_id` (pointing at a package already generated by `bdd_playwright_service`) or a direct `package_url`, plus the `target_url` to record against. The service creates the job in PostgreSQL, returns a `job_id` immediately, and runs the actual execution as a detached background task so the caller can poll for status rather than block on a multi-minute browser run.

Inside that background task the execution engine resolves and downloads the `playwright-bdd` package (a license-gated service-to-service call when a `bdd_job_id` is given, since the bdd download endpoint fails closed on unauthenticated in-cluster traffic), installs its dependencies with `npm ci|install --ignore-scripts`, compiles the Gherkin features into runnable specs with `npx bddgen`, and then runs `npx playwright test --reporter=json,html`. Playwright records one `.webm` per scenario. The engine keys each recording by the package's `@clip-<n>` tag (falling back to a `feature__scenario` slug for plain-Playwright packages) so every clip joins 1:1 back to the orchestrator's narration lines. Recorded clips are optionally transcoded to H.264 MP4 on persist.

When the run finishes the engine writes the summary, per-test results, HTML report URL, artifact paths, and the scenario-clip manifest back onto the job row and marks it completed. The polling caller then fetches the full result and streams each clip out through a tenant-scoped, path-confined `FileResponse` route, re-publishing the footage into orchestrator storage where the video compiler can pick it up anonymously.

The service is stateful but pod-local: clips and HTML reports persist to `/app/data/jobs` on the pod's own disk and are served back through the stream-through routes, which is why it runs at `replicas:1` — a second replica would not hold the artifacts a polling client asks for. It executes tests; it does not author them. The whole run is spawned as its own process group (`start_new_session=True`) so that on a wall-clock timeout the entire `npx → node → browser → ffmpeg` tree can be killed as a unit while already-recorded clips are salvaged from disk, turning a record stage that used to burn its full wall budget into one that finishes seconds after the last test.

## Features

- **Playwright package execution** — downloads, installs, compiles (`bddgen`), and runs a generated `playwright-bdd` package end-to-end so the orchestrator gets recorded footage without hosting a browser toolchain itself
- **Per-scenario clip harvesting** — captures one `.webm` per scenario keyed by its `@clip-<n>` tag so each recording joins 1:1 to a narration line downstream in the `demo_video` pipeline
- **Async job model** — returns a `job_id` immediately and runs execution in a background task so callers poll for status instead of holding a multi-minute HTTP connection open
- **Idempotent re-polling** — the orchestrator re-polls the same job across ~1800s of headroom; `max_run_seconds` (1500) is kept under that total so the record stage keeps polling rather than the job dying first
- **killpg + salvage** — spawns the run as its own process group and, on wall-timeout, SIGTERM→SIGKILLs the whole tree while salvaging per-scenario recordings already written to disk
- **MP4 transcoding** — optionally transcodes recorded WebM clips to H.264 MP4 on persist so downstream consumers get a broadly compatible container
- **Tenant-scoped artifact access** — every read route runs `_enforce_job_tenant()` which 404s on cross-tenant `job_id` (no enumeration side channel), closing a prior BOLA where any authenticated caller could read another tenant's jobs and artifacts
- **Subprocess env hardening** — strips the child process environment to a minimal allowlist (no `DATABASE_URL`/secrets reachable by a malicious `package.json` preinstall) while still passing through `PLAYWRIGHT_BROWSERS_PATH`, and writes login creds to a mode-0600 `.env` loaded via a `dotenv/config` shim rather than the process environment
- **Per-tenant rate limiting** — Redis-backed request throttling plus per-tenant concurrent-job counters so one tenant cannot saturate the single replica
- **Background cleanup loop** — periodically reaps stuck jobs (30 min) and retires old completed/failed jobs (14-day retention) so pod-local disk does not grow unbounded
- **Standard health probes** — liveness, readiness (DB + Redis), and K8s alias paths for orchestration

## Authentication

Inbound requests carry the license token as `X-Tenant-Id: Bearer <license_token>` — **not** the `Authorization` header, which is reserved for caller-side Keycloak auth. The `AuthMiddleware` (re-exported from `w2v_common`) introspects the token against the licenses service and caches the result for 5 minutes (`AUTH_CACHE_TTL=300`). Auth is enabled by default (`AUTH_ENABLED=true`); anonymous calls to `/api/test-runner/*` get 401.

| Priority | Method | Details |
|----------|--------|---------|
| 1 | License token | `X-Tenant-Id: Bearer <token>` introspected against the licenses service, cached 5 min |
| 2 | Trusted network | Bypass for private CIDRs (`127.0.0.1/32`, `::1/128`, `172.16.0.0/12`, `10.0.0.0/8`); OFF by default (`AUTH_TRUST_INCLUSTER_IDENTITY=false`) |

Only the health/probe paths are exempt: `/health`, `/health/live`, `/health/ready`, `/healthz`, `/readyz` (plus `/`, `/docs`, `/redoc`, `/openapi.json`, `/metrics` for the OpenAPI/docs surface). There is no Postgres RLS — tenant isolation is enforced application-side by `_enforce_job_tenant()` on every read route.

The outbound S2S package download re-uses the request-scoped license token: it is captured at `POST /execute` (`_extract_license_token`) and threaded into the detached background task, because the identity ContextVars set by `AuthMiddleware` do not survive into a `BackgroundTasks` job. The token is forwarded as `X-Tenant-Id: Bearer <token>` **only** to the trusted internal bdd download — never to an arbitrary external `package_url` (credential-leak guard).

## API Endpoints

Routes are UNVERSIONED and mounted under `/api/test-runner`.

### Test Runner `/api/test-runner`

| Method | Path | Description |
|--------|------|-------------|
| POST | `/execute` | Submit a job (`bdd_job_id` or `package_url` + `target_url`); returns `job_id`, runs async |
| GET | `/{job_id}` | Poll job status |
| GET | `/{job_id}/result` | Full result including `scenario_clips` |
| GET | `/{job_id}/report` | HTML report URL and artifact paths |
| GET | `/{job_id}/clips/{clip_key}/video` | Stream a recorded per-scenario clip (tenant-scoped, path-confined) |
| GET | `/{job_id}/artifacts/{path}` | Serve a persisted report artifact |

### Health

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Service info and endpoint listing |
| GET | `/health` | Liveness probe |
| GET | `/health/live` | Liveness probe |
| GET | `/health/ready` | Readiness probe (checks DB and Redis) |
| GET | `/healthz` | K8s liveness alias of `/health/live` |
| GET | `/readyz` | K8s readiness alias of `/health/ready` |

## Configuration

All configuration via environment variables.

| Variable | Default | Description |
|----------|---------|-------------|
| `API_HOST` | `0.0.0.0` | Listen host |
| `API_PORT` | `6316` | Listen port (base `Settings` rejects `8000`) |
| `API_DEBUG` | `false` | Enable debug mode / error detail in envelope |
| `AUTH_ENABLED` | `true` | Toggle license-token authentication middleware |
| `AUTH_DEFAULT_TENANT_ID` | `default` | Tenant for the trusted-network synthetic-identity path (OFF by default) |
| `AUTH_CACHE_TTL` | `300` | License introspection cache TTL (seconds) |
| `AUTH_TRUST_INCLUSTER_IDENTITY` | `false` | Enable the trusted-network bypass |
| `LOG_LEVEL` | `INFO` | Logging level |
| `DATABASE_URL` | `postgresql+psycopg://localhost:5450/frontend_test_runner` | PostgreSQL connection (psycopg3) |
| `DATABASE_POOL_SIZE` | `10` | Connection pool size |
| `DATABASE_MAX_OVERFLOW` | `20` | Max connections beyond pool size |
| `REDIS_URL` | `redis://localhost:6390/0` | Redis URL (rate limiting + concurrent-job counters) |
| `PLAYWRIGHT_BROWSERS_PATH` | `/ms-playwright` | Baked-in browser location; **must** be inherited by the runner subprocess |
| `EXECUTION_MAX_WORKERS` | `4` | Max parallel Playwright workers |
| `EXECUTION_DEFAULT_TIMEOUT_PER_TEST_MS` | `30000` | Default per-test timeout (ms) |
| `EXECUTION_MAX_RUN_SECONDS` | `1500` | Wall-clock ceiling per `playwright test` run (kept under the orchestrator's ~1800s re-poll) |
| `EXECUTION_MAX_CONCURRENT_EXECUTIONS` | `5` | Max concurrent execution jobs |
| `EXECUTION_CONVERT_CLIPS_TO_MP4` | `true` | Transcode recorded WebM clips to H.264 MP4 on persist |
| `EXECUTION_ARTIFACTS_ROOT_DIR` | `/app/data/jobs` | Pod-local directory for persisted reports and clips |
| `RATE_LIMIT_REQUESTS_PER_MINUTE` | `20` | Max requests per minute per tenant |
| `RATE_LIMIT_CONCURRENT_JOBS_PER_TENANT` | `3` | Max concurrent jobs per tenant |
| `CLEANUP_RETENTION_DAYS` | `14` | Days to retain completed/failed jobs |
| `CLEANUP_STUCK_JOB_TIMEOUT_MINUTES` | `30` | Minutes after which a processing job is considered stuck |

## Architecture

```
src/
├── asgi.py                    # FastAPI app, lifespan (DB + Redis + cleanup loop), middleware stack, root/health, error envelope
├── config.py                  # Pydantic settings extending w2v_common; port 6316, execution/rate-limit/cleanup groups
├── errors.py                  # {error:{code,message,status,request_id}} envelope helpers
├── api/
│   ├── health.py              # Liveness / readiness (DB+Redis) / healthz / readyz probes
│   ├── routes.py              # /api/test-runner execute + poll + result + report + clip/artifact streaming
│   └── schemas.py             # Request/response DTOs (TestExecutionRequest, ScenarioClip, TestExecutionResult, ...)
├── auth/
│   └── middleware.py          # License-token AuthMiddleware (delegates to w2v_common)
├── middleware/
│   ├── rate_limiter.py        # Redis-backed per-tenant rate limit + concurrent-job counter
│   └── request_id.py          # Binds request_id ContextVar (registered last = outermost layer)
├── cache/
│   └── redis_client.py        # Async Redis client init/close lifecycle
├── database/
│   ├── connection.py          # Async engine (psycopg3) + health_check
│   ├── session.py             # get_db_session async context manager
│   ├── models.py              # TestExecutionJob + TestRunnerUsage ORM (tables test_execution_jobs, test_runner_usage)
│   └── migrations/            # Alembic (001_initial, 002_scenario_clips)
└── services/
    ├── execution_engine.py    # download → npm install → bddgen → playwright test → killpg/salvage clips
    ├── job_manager.py         # Job state machine (create / mark_processing / mark_completed / mark_failed)
    └── cleanup_service.py     # Stuck-job + retention sweeper (driven by the lifespan cleanup loop)
```

## Dependencies

- **w2v_orchestrator** — upstream caller; its `demo_video_record` stage submits jobs via `FrontendTestRunnerClient`, re-polls the idempotent FTR job, and re-publishes each clip into orchestrator storage
- **bdd_playwright_service** — generates the `playwright-bdd` package (Gherkin features + steps + `@clip-<n>` tags); FTR downloads it via a license-gated S2S call and consumes the `.feature`/step files
- **licenses service** — validates license tokens via introspection (5-minute cache)
- **PostgreSQL 18** — persistent job/usage state (`test_execution_jobs`, `test_runner_usage`) via psycopg3, routed through PgBouncer (`pgbouncer.pgbouncer:6432`) in-cluster
- **Redis** — per-tenant rate limiting and concurrent-job counters
- **Playwright** — headless browser automation and per-scenario video recording (`npx playwright test`, `npx bddgen`)
- **FastAPI** — web framework
- **Uvicorn** — ASGI server
- **Pydantic v2 / pydantic-settings** — request/response validation and settings
- **SQLAlchemy (async)** — ORM over psycopg3
- **Alembic** — database migrations
- **httpx** — async HTTP client for S2S package download and introspection

## Known Issues

- **`PLAYWRIGHT_BROWSERS_PATH` must be inherited (FTR#37)** — `_subprocess_env` strips the child environment to a minimal allowlist so a malicious `package.json` preinstall script cannot read `DATABASE_URL`/secrets, but it MUST pass `PLAYWRIGHT_BROWSERS_PATH` through. The image bakes browsers at `/ms-playwright` and `npm install` runs `--ignore-scripts` (no per-package download), so without this var `npx playwright test` finds no browser, never launches, and produces zero footage while burning the whole wall budget. It is a path, not a secret — safe to pass through.
- **Stale SQLite comment in `models.py`** — a "JSON on SQLite/others" comment is stale; SQLite is never used anywhere in this monorepo. The live wire driver is psycopg3 on Postgres 18.
